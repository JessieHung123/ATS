# ATS 職能評分教學系統

HR 課堂用的 ATS 模擬系統（FastAPI 後端 + 原生 JS 前端）：把職缺拆成職能矩陣、設定權重與評分尺度、為履歷逐項評分，最後產生面試問題。

## 執行

**最簡單：雙擊 `start.bat`**。第一次會自動建立環境、安裝套件，之後直接啟動並打開瀏覽器（http://127.0.0.1:8765）。關掉黑色視窗即停止。

手動啟動：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --port 8000
```

開啟 http://127.0.0.1:8000 。請固定使用 `127.0.0.1`；`localhost` 會自動轉址，避免不同網址各自保存 API Key。

- **有 Gemini API Key**（到 [Google AI Studio](https://aistudio.google.com/apikey) 免費申請；在右上角「設定」輸入，或設定環境變數 `GEMINI_API_KEY`）：職能拆解、逐職能評分、面試問題由 Google Gemini 產生；模型可在「設定」切換：`gemini-3.5-flash-lite`（預設，最快）、`gemini-3.6-flash`（平衡）、`gemini-3.8-flash`（最聰明但較慢），也可用環境變數 `GEMINI_MODEL` 指定預設值。瀏覽器輸入的金鑰只存在該瀏覽器的 localStorage；VS Code 內建瀏覽器與 Chrome 需各自儲存。免費版有每日使用上限，且內容可能被 Google 用於改善產品，請只使用虛構履歷。
- **沒有 API Key** 或取消勾選「使用 AI」：全部改用規則式（職能字典、關鍵字比對、範本題目），完全不需連網或 API Key。
- 「動詞 + 成果 + 量化數據」偵測器永遠是規則式，判斷理由逐句列出，方便學生理解。
- 資料存在瀏覽器 localStorage，重新整理不會遺失；「設定 → 清除所有資料」可重來。

## 四個模組

| 模組 | 功能 |
|---|---|
| 1 職缺拆解 | 3 個範例職缺一鍵帶入；結構化欄位（職稱、年資、學歷、必備、加分）；拆解為硬實力／軟實力／門檻條件；可新增、刪除、改名職能 |
| 2 權重與評分標準 | 專業技能／專案經驗／軟實力權重滑桿（總和固定 100%）；均衡／重技術／重經驗／重潛力預設組合；同一批履歷在各組合下的分數與名次變化；0–3 分 Rubric（全域與個別職能）；門檻「直接淘汰／扣分」 |
| 3 履歷評分 | 貼上文字或一次上傳多份 PDF／Word；啟用 AI 且設定 API Key 時，AI 會整理履歷資訊（掃描型 PDF 也會嘗試辨識），並以候選人姓名按鈕保存整理結果，點選即可載入姓名與整理後的履歷內容；逐句 🟢🟡🔴 標色；每個職能的得分卡（分數、佐證原文、判斷理由）；Match Score、雷達圖與大類長條圖；多份履歷排名；缺口分析 |
| 4 面試問題 | 驗證型、補洞型、STAR 行為面試題，每題附「面試官想聽到什麼」與評分要點；可列印 |

### 計分方式

- 每個職能 0–3 分；必備職能權重 ×2、加分 ×1，算出各大類得分（0–100）。
- 每項職能另有獨立權重（1–100，預設 1），在第二部分「評分尺度」調整。大類得分 = Σ（職能得分 ÷ 3 × 職能權重 × 必備／加分倍率）÷ Σ（職能權重 × 必備／加分倍率）× 100。舊資料沒有此欄位時視為 1；只調整權重會直接重算既有評分，不需再次呼叫 AI。
- Match Score = Σ（大類權重值 × 大類得分）÷ 有職能的大類權重值總和；沒有職能的大類不參與計算。滑桿獨立調整，總和不必等於 100；例如 60、35、25 換算為 50%、29.17%、20.83%（三大類皆有職能時）。
- 門檻條件「確定不符合」時：直接淘汰，或扣設定的分數；無法判斷時不扣分，但列入缺口分析。

## 專案結構

```
backend/main.py       FastAPI 路由，並提供前端靜態檔
backend/ai.py         Gemini 呼叫：職能拆解、履歷評分、面試問題（含範本備案）
backend/matrix.py     職能矩陣結構、規則式拆解（職能字典）
backend/scoring.py    規則式評分、權重加總、門檻、缺口分析
backend/sentences.py  動詞＋成果＋數據偵測器
backend/samples.py    範例職缺與範例履歷（虛構）
frontend/             index.html、app.js、styles.css
ats/                  Gemini 共用呼叫（gemini.py）、PDF 解析與關鍵字比對（與舊版共用）
app.py                舊版 Streamlit 介面（streamlit run app.py）
```

> 評分結果僅供教學與初篩參考，最終錄用決策應由 HR 與用人主管判斷。AI 已被要求忽略年齡、性別、婚姻等與職務無關的特徵。

## 職缺建議與人工確認

職稱旁的「AI 填寫空白欄位」使用既有 Gemini 串接及 `POST /api/job/autofill`，補齊年資、學歷、必備、加分及 JD，只填空白處。提供 JD 時優先依 JD 整理；沒有 JD 時標示一般性建議。填入內容可直接修改、刪除，確認後即可拆解職能。另一個「另產生職責與技能草稿」按鈕只產生清單草稿，不會填寫這些欄位。

右上角「API 已設定，尚未驗證呼叫」僅表示伺服器有金鑰；填寫請求成功後才顯示「Gemini 呼叫成功」。此填寫功能失敗時會顯示連線、模型、額度或回傳格式錯誤，保留原有欄位，不改用規則式結果。Windows 10013 表示服務的對外連線被執行環境或防火牆拒絕，需允許服務連網。

可執行 `.\.venv\Scripts\python.exe tests/browser_autofill.py`，在 8765 服務上以獨立瀏覽器設定檔測試兩個職稱、JD 優先、畫面填值及後續拆解。此測試會實際呼叫 Gemini 並使用 API 額度；一般回歸測試不會。

1. 輸入職稱或 JD，按「AI 產生職缺條件」。新路由 `POST /api/job/suggest` 沿用現有 Gemini JSON Schema 呼叫，回傳工作職責、技能與工作相關能力草稿。
2. 有 JD 時優先整理 JD；只有職稱時標示「一般性建議，並非企業已確認的招募條件」。沒有金鑰、關閉 AI 或 AI 失敗時，使用規則式草稿，不冒充 AI 結果。
3. 草稿每項可新增、刪除或修改，按「確認並套用全部草稿」才加入職缺；原始 JD、手動必備與加分欄位保留。自行輸入的職缺可按「確認目前職缺內容」。修改職缺後必須重新確認。
4. 按「拆解職能」，可調整硬實力、工具技能、專業知識、工作相關軟實力，編輯關聯理由、必備／加分、關鍵字與名稱。四分類與原有三大評分權重分開設定，繼續使用 0–3 分 Rubric。
5. 職缺、職能或 Rubric 變動會將舊分析標記為待確認，需重新分析。AI 佐證必須能在履歷原文找到；找不到則標記待人工確認。未確認的門檻不會扣分或直接淘汰。

新增功能位於 FastAPI／原生 JS 介面；舊版 Streamlit 保留原本關鍵字與履歷評分流程。

## 驗證

```powershell
.\.venv\Scripts\python.exe -m compileall backend ats
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

測試不需要金鑰、不會呼叫外部 AI。後端啟動於 8000 埠後，Windows 安裝 Edge 的環境可執行瀏覽器操作檢查：

```powershell
.\.venv\Scripts\python.exe tests/browser_smoke.py
```

瀏覽器測試使用獨立暫存設定檔與虛構履歷，不讀取日常瀏覽器資料。實際 Gemini 的品質、額度與可用性仍需在安全設定金鑰後人工驗證。
